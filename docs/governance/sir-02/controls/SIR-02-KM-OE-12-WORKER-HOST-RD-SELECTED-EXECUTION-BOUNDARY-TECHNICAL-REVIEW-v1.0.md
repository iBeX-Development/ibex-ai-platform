**Distinction:** closing an owned stream or unreferencing a Node child only changes local handle/event-loop behavior. A Worker `exit` observation establishes that named process exit, subject to identity binding, but says nothing by itself about descendant/conhost/helper membership or all handle disposal. A qualifying **safe isolation** state would have to be independently defined and show that late activity cannot influence authoritative state while leaving no unidentified process collateral to a destructive operation. **Disposal** would additionally require the governed completion/resource-state evidence for every owned member/handle. The retained source demonstrates none of the latter two under a real unresponsive Worker. The helper `≤5,000 ms` ceiling is a design target, not a measured or approved disposal capability; no timer is resettable into proof.

**D2 finding: `Design STOP Valid — New isolation-boundary design required`.** The STOP follows from `RD/supervisor.mjs:21–28,129–168`, `RD/controller.mjs:28–34,123–140`, `RD/identity.ps1:40–61`, `RD/worker.ps1:43–75`, unproven actual membership and the rejected preflight §§2–5. No existing path was omitted that could establish a finite, non-destructive disposition of a real hung Worker and timed-out helpers. This finding validates the design's STOP, **not** a D2 mechanism, GAP-B closure or worker-disposal proof.

## 4. Separate design decision and proof obligations

The candidate direction for a **future separate decision** is an outer-authority-owned isolation boundary whose admission and observation cover every actual Worker, Node, possible conhost and identity helper, while the Controller fences all late results. This is a question to design and review, **not** a choice of Job, process termination, sandbox, service or other implementation and not a substitution of D1 for owner-selected D2. That future decision must establish whether a finite qualifying **non-destructive safe isolation** state can be defined for a Worker still physically live; if the approved criterion instead requires actual bounded process/resource disposal, containment alone is insufficient. If neither can be proven, return D2 to the owner rather than weaken the requirement silently.

Minimum proof obligations for that separate design: independent creator/admission receipts for the complete actual member set; trusted run/generation and handle/session/Job binding; PID-reuse-resistant full tuple and fresh ≤500 ms revalidation before every process action; safe authority limits for a timed-out CIM helper and a real unresponsive Worker; one non-resetting total/disposal/helper deadline; explicit success, timeout, exception, cancellation, partial failure and `finally` handle order; no destructive unknown-member Job-wide or PID fallback; immutable closure/cutoff, late-result rejection and zero post-closure authoritative mutation; retained direct WH-03, WH-08, WH-09 and WH-10 negative-path evidence after separate authorization. WH-03/09 prelaunch STOP and WH-08 synthetic STOP remain **nonproof**.

Before source work, the sequence required by the published owner decision §3 remains **separate isolation-boundary design → technical review → exact-byte publication → owner approval → applicable implementation change control → bounded source-change authorization**. A new key, ledger/store, independent receipt producer, OS isolation component, service, privilege, account/ACL, dependency, environment/CIM configuration, executable approval or changed criterion each needs its own applicable change control. No such resource is created or approved here.
