## 1. Boundary and preflight decision

The next CIM environment validation is intended to be **read-only and non-destructive**. The existing OE-12 attribution criteria remain unchanged. Option A remains `Not Currently Feasible`; Option B remains `Needs Clarification` and unapproved. Diagnostic v4 is `Not Proposed`; Smoke v5 and formal retry `0003` are `Not Authorized`; OE-12 is `Not Executed`.

This document is a **normative contract for future exact source**, not the source itself. No text here proves that an executable branch exists or that Windows PowerShell 5.1 can safely cancel a blocked CIM call. The pre-execution reviewer must inspect the exact bytes of every future source file and fill the branch/line evidence for every applicable row below. A comment, prose design, API name without a reachable executable branch, or an untested assumption about disposal is insufficient. If any row lacks a safe, bounded branch: **Preflight Gate = STOP — Source/Safety Gap**. No owner execution authorization may issue from a stopped gate.

The current plan assumes no new synthetic Node/conhost process is spawned. If later source introduces a child process, launcher, release signal, retained handle, Job, or watchdog process, that is a separately reviewed scope change. Its early-exit, exception, cancellation, ownership, and cleanup branches must all be mapped before authorization. An `N/A` claim is valid only when a static exact-source review proves that the resource/action is absent in every reachable branch.

## 3. Ownership and fresh revalidation contract

For any process-sensitive action, the established identity is **PID + image path + parent PID + creation time + unique synthetic run token + creation/assignment evidence**, plus retained handle, session, and Job evidence where applicable. PID membership alone, image alone, a prior diagnostic's PID, and creation-time proximity do not prove ownership. The future source must retain the established tuple and compare it to a **fresh current tuple immediately before every process-affecting action**, including a cooperative release signal. Fresh reads must use the exact approved PID-bound `Get-CimInstance` call for parent/creation/Node command line and handle-bound `QueryFullProcessImageNameW`, `GetProcessTimes`, `WaitForSingleObject`, and `ProcessIdToSessionId` as applicable. For any Job, freshly query membership with `QueryInformationJobObject` and verify every member and the creation/assignment receipt before acting.

The comparison branch must STOP on PID reuse, creation-time mismatch, parent mismatch, image mismatch, token mismatch, unexpected Job member, missing/stale receipt, lost handle, or incomplete query. It may not use cached identity to overcome a failed fresh query. The future **read-only** validation should need no process-affecting action; if an already authorized synthetic context has an owner-provided cooperative release, the exact source and separate authorization must map that action and its fresh check. This remediation does not authorize child creation, cooperative signaling, or any process action.

## 4. Cleanup and fallback contract

**No destructive fallback is permitted.** Future validation source must contain no reachable cleanup call to `TerminateJobObject`, `TerminateProcess`, `Stop-Process`, `taskkill`, or kill-on-close, and must never terminate an unidentified or unverified PID. Any fallback branch must be subject to the same fresh ownership and membership gate as its primary path; a `finally` block cannot bypass that gate. Smoke v4's unknown-member/Job-wide fallback and Diagnostic v3's targeted `TerminateProcess` branch cannot be reused as written. Their historical results remain unchanged.

On **every** success, exception, timeout, partial result, and cancellation path, the future source must implement this exact order in an outer `finally` (with guarded substeps so an early cleanup error does not skip later safe disposal):

1. Stop issuing new CIM queries; record the in-flight query set and cancellation request.
2. Record final probe state and primary failure before cleanup can alter it.
3. If a separately authorized synthetic process exists and release is applicable, freshly revalidate its complete identity and membership, then request **cooperative** exit using the separately reviewed exact source call. Otherwise record source-proven `N/A`; do not invent a release path.
4. Use a bounded `WaitForSingleObject(retainedOwnedHandle, <approved bound>)` or reviewed equivalent. If the process does not exit, set **`STOP / Not Executed`** for this attempt, preserve the still-live resource state, and seek a new governance decision. Do not broaden cleanup into a destructive fallback.
5. Read-only verify current identity and exit/state with `GetProcessTimes`, `WaitForSingleObject`, approved local `Get-CimInstance`, and current Job membership where applicable. A failed identity query is unresolved, not a positive exit assertion.
6. Dispose completed `PowerShell` pipeline and any separately approved `CimSession` using its exact reviewed disposal call. If an in-flight call cannot be safely quiesced and disposed within the approved bound, STOP; do not claim cleanup complete.
7. Close only owned read-only process/Job handles via `CloseHandle` in explicitly reviewed order. A Job handle may close only after verified non-destructive Job limits; a kill-on-close Job must not be closed while membership is unresolved. Record each close result.
8. Remove only diagnostic-owned temporary files by validated absolute `-LiteralPath`; remove only their empty owned directory. Retained immutable evidence is never deleted.
9. Verify every diagnostic-owned handle/session/file is gone using the resource ledger and `Test-Path -LiteralPath` for exact temporary paths. Record unresolved residue without masking the primary failure.
10. Emit final sanitized cleanup evidence, including primary and secondary cleanup errors, exact resource states, timestamps, and whether the run stopped before a validation result.

`STOP / Not Executed` is a **preflight or interrupted-attempt classification**, not a fourth completed CIM feasibility result and not a change to canonical OE-12 status. A future completed validation still uses only the existing plan's `PASS — Option B Environment Feasible`, `FAIL — Option B Environment Not Feasible`, or `Needs Clarification` decision set.

## 5. Outer watchdog contract

An outer watchdog may observe only elapsed time, the reviewed asynchronous CIM operation's completion state, and its own diagnostic-owned resource ledger. It may request cancellation only through an exact reviewed, bounded, **non-destructive** Windows PowerShell 5.1 API path, then verify quiescence before disposal. It may not query broad host process lists, terminate processes or Jobs, bypass the ownership gate, close a kill-on-close Job, or perform broader cleanup than the main source. If a child watchdog is proposed, its launch, early exit, exception, ownership, timeout, cancellation, and cleanup paths require a separately reviewed design; none is authorized here.

The previous plan's candidate `BeginStop`/`EndStop` model is **not proven safe by naming those APIs**. The future exact-source reviewer must verify the available Windows PowerShell 5.1 overloads, call sequence, second finite stop bound, behavior when CIM/provider does not quiesce, and disposal branch. If safe non-destructive bounded cancellation cannot be established before execution: **STOP — Source/Safety Gap**. Do not run a probe to discover an unsafe stop behavior.

## 6. Mandatory exact-source review gate

Before any future preparation authorization becomes execution authorization, an independent reviewer must inspect the exact, versioned source bytes and produce a matrix for **every reachable exit** with: source file/function/line; trigger condition; precise API/native call and parameters; process/resource affected; established and freshly revalidated ownership evidence; resource state; cleanup call/order; and retained output field/path. The reviewer must verify executable `try`/`catch`/`finally` control flow, not a comment or this prose contract. The review must explicitly inspect source for prohibited destructive calls and for hidden calls in dependencies/helpers. No test-only or temporary source may be executed before this gate.

The review records **exactly one**: `Accepted — Exact Source Safe for Authorization`, `Needs Clarification`, or `Rejected`. Only `Accepted` permits a later **separate owner decision** on a bounded validation execution. It does not select Option B or authorize Diagnostic v4, Smoke v5, or formal retry `0003`.

At governance review, STOP if any proposed path needs destructive process cleanup, incomplete ownership evidence, Administrator/UAC elevation, CIM/WMI/service configuration change, persistent execution-policy change, dependency installation, network access, production/live data, OE-12 criterion modification, or production/runtime code change. This document proposes no workaround for any STOP condition.
