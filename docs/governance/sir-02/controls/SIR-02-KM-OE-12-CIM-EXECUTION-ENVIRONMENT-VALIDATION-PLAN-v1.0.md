The owner decision and its assessment establish that Option A is **Not Currently Feasible** under the approved attribution contract. It may create only temporary local evidence output and must delete those temporary files in a verified `finally` path after retaining the governed result. It must not spawn a Node/conhost topology, enumerate unrelated host processes, alter services or policy, open remote CIM sessions, or terminate any process. The absence of an already authorized, live synthetic topology makes full Option B feasibility **Needs Clarification**, not an inferred PASS. The future owner must separately authorize the exact source and execution before any query is run.

## 2. Future read-only probe set and evidence fields

The following is a call-level design, **not an executable script**. Every target PID must come from an independently reviewed synthetic run context, with a unique run token and creation/assignment receipts. No PID may be discovered by broad enumeration or accepted solely because it appears in a Job member list.

P0/P1 establish environment diagnosticability only. P2 on an unbound current process, if separately approved as a provider canary, cannot establish Node/conhost ownership or yield PASS. P3 is permissible only if a separately authorized synthetic context is already live and its exact source, target identities, and handle/assignment receipts have passed pre-execution review. The future source must use parameterized integer PIDs, reject wildcard or remote targets, and avoid retaining a raw command line except the minimum synthetic token/probe-path assertion and sanitized failure detail. The `Win32_Process` query and its local WMI behavior are documented for Windows PowerShell 5.1 by [Microsoft](https://learn.microsoft.com/en-us/powershell/module/cimcmdlets/get-ciminstance?view=powershell-5.1); the plan makes no assertion that the current environment will return those fields.

## 3. Exact pre-execution source review and bounded invocation contract

The future source must be reviewed **before execution**, including every function/call that implements P0–P3 and all error and cleanup branches. Review must confirm one fixed local target set, `-OperationTimeoutSec 2` for each CIM call, a finite outer deadline per probe, no interactive prompt, no network/remote parameters, and no mutation or destructive process call. To make an outer deadline observable without a child process, the proposed wrapper uses `[System.Management.Automation.PowerShell]::Create()`, `.AddCommand(<approved command>)`, `.AddParameter(...)`, `.BeginInvoke()`, and the returned `IAsyncResult.AsyncWaitHandle.WaitOne(<finite deadline>)`; completion uses `.EndInvoke(asyncResult)`. Input must be closed before `BeginInvoke` if an explicit `PSDataCollection` is used. This is a **candidate API contract**, not authorization or proof that cancellation is safe on this host. [Microsoft's Windows PowerShell API reference](https://learn.microsoft.com/dotnet/api/system.management.automation.powershell.begininvoke) documents the asynchronous invocation contract.

On outer timeout, the candidate may call `.BeginStop(null, null)` and wait for that stop result within a second finite deadline, then `.EndStop(stopResult)` and `.Dispose()` only after invocation quiescence. The exact 5.1 overload and actual bounded-stop behavior must be verified in the future source review. It must **not** use `Stop-Process`, `TerminateProcess`, `TerminateJobObject`, Job-handle-close kill-on-close, `taskkill`, or a child-process watchdog. If the reviewed source cannot prove a bounded non-destructive stop and subsequent disposal for every call, **Preflight Gate = STOP**; do not execute in order to discover whether a hung call can be cleaned up. No timeout may be reported as a successful query or silently retried. [Microsoft documents `PowerShell.Stop()` as synchronous](https://learn.microsoft.com/en-us/dotnet/api/system.management.automation.powershell.stop), so a bare blocking `Stop()` is not an acceptable outer-timeout mechanism.

The exact source review must identify the temporary output directory (restricted to the separately authorized local temp root), fixed filenames, creation and cleanup calls, and retained governed output location. Any inability to verify deletion or handle disposal is a failure/clarification, never PASS. No temporary script, adapter, probe, or execution artifact is created by this plan.

The future source must also map **pre-launch/pre-query rejection**, **serialization failure**, and **cleanup failure while handling an earlier error** to the exception/`finally` rows. It must preserve both the primary failure and cleanup failure. A native API failure must capture `GetLastWin32Error()` immediately before any intervening native call. No raw host process list or unrelated process command line may enter the retained output.

## 5. Ownership, identity, and safety gate

For any process-sensitive query, the minimum combined identity is **PID + image path + parent PID + creation time + unique synthetic run token + creation/assignment evidence**, plus retained handle, session, and Job evidence where applicable. Compare CIM fields with handle-bound native observations for the *same* live instance; reject PID reuse, missing token, missing/unstable creation time, changed parent, mismatched image, and unexplained Job membership. A Job PID list, timestamp proximity, or a PID-only lookup is never ownership proof. The conhost token may be bound through the verified synthetic Node parent and immutable creation/assignment receipt only when the approved attribution contract permits that exact relationship; otherwise classify as ambiguous. Previous-run identities cannot be imported.

This plan requires **no destructive process action**. If a later separately proposed diagnostic ever requires one, ownership and the full current Job/member set must be freshly revalidated immediately beforehand and separately authorized. This plan does not authorize or design that action. If the current environment cannot supply a live approved synthetic context without creating one in this read-only validation, record `Needs Clarification`; do not use another tenant, host process, prior run, or production data as a substitute.
