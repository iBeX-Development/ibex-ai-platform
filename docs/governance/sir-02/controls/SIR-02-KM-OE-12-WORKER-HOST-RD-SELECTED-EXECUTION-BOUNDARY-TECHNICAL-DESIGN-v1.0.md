## 3. End-to-end proposed state and path contract

This is a **hypothetical** transition table. No transition is executable from this record. Every future branch must later map `trigger → exact reviewed source/function → exact API/call → state transition → ownership check (Required or Not Applicable with reason) → cleanup/disposal → retained evidence`. All clocks must use monotonic start/end stamps and record expiry. The approved R&D plan's proposed bounds remain startup 8,000 ms; provider observation 10,000 ms; authoritative closure 2,000 ms; cooperative cancellation 2,000 ms; ownership freshness 500 ms; disposal/safe isolation 5,000 ms; total run 45,000 ms. The helper ≤5,000 ms is a selected **design target**, not a proven capability. A future source review must identify the exact clock and API at each event below.

## 5. D2 feasibility gate — handle close and fallback analysis

The retained source does not justify finite safe disposal under a real unresponsive Worker. `RD/supervisor.mjs` may start a Worker; `RD/supervisor.mjs:observeIdentity()` and `RD/controller.mjs:independentIdentity()` independently start PowerShell helpers. Those helpers can stall during CIM. Their timeout branches call `child.unref()` and destroy stdout/stderr pipes without an observed exit or proven isolation. Supervisor's CANCEL sends cooperative `worker.stdin.end()` after a partial identity check, waits through grace/disposal races, and can leave the Worker live; its `finally` starts a **new** 5 s observation window and can again `unref()`/destroy streams. Controller's `finally` can `unref()` and destroy Supervisor streams without proving Supervisor, Worker or helper exit. Closing a stream/handle or unreferencing a `ChildProcess` is not termination, safe isolation, or disposal evidence. Audit or identity exceptions can interrupt these paths. The package has no destructive fallback, which preserves the prohibition, but that absence does not prove finite cleanup.

The actual complete Node/conhost/helper membership and creation/assignment provenance are not established. If a future Job Object is considered, Job membership alone cannot prove safe ownership. Closing a kill-on-close Job handle or calling `TerminateJobObject` while any member is unidentified would risk collateral termination. A process-specific termination fallback against an unverified PID is equally prohibited. This design selects **no** Job, process termination, service, sandbox, or other D2 implementation. A qualifying D2 design must first identify its owner/admission rule, all actual members and handles, non-destructive finite isolation semantics, control of an unresponsive CIM operation and timed-out identity helper, exception/timeout/finally disposal ordering, and direct evidence of a finite result **without** an unidentified-process effect. Present source and retained evidence cannot establish that guarantee.

**D2 feasibility conclusion: `Design STOP / D2 Not Yet Feasible`.** Worker disposal remains **OPEN proof obligation**; the helper ≤5,000 ms target is **unproven**. Do not replace D2 with D1, infer safety from terminal closure, prelaunch WH-03/09 or synthetic WH-08, or begin disposal source work. If a compliant non-destructive boundary cannot be specified, return D2 to the owner for a new decision.
