## 3. GAP-B — bounded CIM completion boundary

Keep **provider-level quiescence** separate from **worker/collector quiescence**. The former requires proof that the exact CIM provider operation and owned session/pipeline have ended, no callback/result can arrive, state is stable, and disposal completes within the approved finite bound. The latter can show that late worker output cannot alter the authoritative collector, but cannot by itself prove shared-provider work stopped. No criterion may be changed by rewording one as the other.

| B1. **Already proven:** the existing in-process source bounds one wait, requests stop, and fails closed on unresolved work; the rejected safety review found that it does **not** prove finite provider quiescence. The published assessment distinguishes a stable collector from a stopped provider. **Requires read-only inspection:** whether locally retained, supported API documentation or immutable prior observations provide a stronger exact-provider completion guarantee and whether any existing isolation boundary actually contains the provider. **Would require execution/new boundary:** demonstrating live host reliability, cancellation timing, callback drain, a new worker/provider boundary, or fault-injection behavior. **Not provable under the current in-process boundary:** universal finite completion of a nonresponsive shared CIM provider from a client timeout or `BeginStop`/`EndStop`/`IsCompleted`/`Dispose()` observation alone.

GAP-B future outcome must be exactly one of `Feasible`, `Not Feasible`, or `Needs Clarification`. `Feasible` requires all B1–B6, including **actual provider-level** bounded completion and disposal under the unchanged criterion, to be supported by retained evidence and documented guarantees with no STOP condition. `Not Feasible` requires a supported contradiction showing no permissible non-destructive boundary can meet the literal criterion. If provider containment or completion remains unproved, return `Needs Clarification` and preserve the existing `Not currently feasible` operational boundary finding; do not infer feasibility from worker/collector fencing. Neither outcome authorizes a criterion change or probe.
